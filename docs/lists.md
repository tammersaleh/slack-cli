# Slack Lists

Measurements and reasoning behind the rules in `CLAUDE.md`. `CLAUDE.md` holds the current rule for each topic. This file holds how it was found.

## Reads

Slack Lists (`list info`/`schema`/`records`/`find`, cmd/list.go + cmd/list_render.go) ride the session client and `PostInternalForm` only, no two-client split: on Enterprise Grid the org token serves `files.info`, `lists.records.list`, and `search.files` alike (verified live 2026-11-04, docs/lists-plan.md). `files.info` is decoded into the local `listFile` struct because slack-go's `File` drops `list_metadata` and `list_limits`; a file without `list_metadata` is `not_a_list` rather than an empty schema. `list records` reads the schema once before the first page and joins every page's `fields[].column_id` to `schema[].id` **inside the fetch closure** (`renderRecord`), so an unknown `column_id` fails the page as `list_schema_mismatch` - an `*output.Error`, so `streamError` makes the trailer terminal with no resume cursor - before any row reaches stdout. Records are decoded with `UseNumber` so timestamps and decimals re-encode verbatim. Column keys are display names deduped by probing (`columnKeys`: `Foo`, `Foo_2`, `Foo` gives `Foo`, `Foo_2`, `Foo_3`), positional against the schema. `withListLimits` is a `streamOption` that copies `row_count`/`archived_row_count` (new optional `output.Meta` fields) into every trailer, failures included. `list find` is `search.files` via `PostInternalForm` with `type:list "<title>"`, one row per match, never a single resolution - titles collide. Unverified: `lists.records.list` on an OAuth bot token (rejected locally as `session_token_required`), record order, and whether `view_id` changes it.

## List and column writes

Slack Lists writes (`list create`/`update`, `list column add`/`rename`/`set-choices`/`delete`, cmd/list_write.go + pure helpers in cmd/list_columns.go) follow the same session-only transport. Rules: every input is validated before the first call (`parseColumnSpecs` builds each column's `options` JSON up front; `resolveColumn` is pure and takes an exact id/key match first, then a case-insensitive name that must be unique - `ambiguous_column` - because keys and ids are Slack-unique while names collide, and the shared fixture has two columns named `Name`); every success row is rendered from the server's returned `list` object (`decodeListResponse` + `listInfoRow`/`columnRow`), never from the request; `lists.columns.delete` is the exception, answering a bare `{ok}`, so its row is the resolved column plus `status`. `list create` runs `lists.create` → one `lists.columns.create` per `--column` → `lists.update` for `--icon`, and a failure after the first call is a **partial row** (`id`, `error`, `detail`, `failed_step`, `failed_column`, `hint` with the exact finishing commands) returned as `*output.ExitError` carrying the classified code - never `*output.Error` (stderr) and never `_meta.error` (which means a truncated stream); the list is never deleted. `set-choices` is whole-set read-then-replace: exact-label matches keep `value` and `color`, new labels get a slug plus `choicePalette[position]`, collisions are `invalid_input`, and `listColumnOptions` keeps unmodeled option keys raw in `Extra` so `default_value` and whatever Slack adds round-trip (a `default_value` naming a removed choice is dropped). Plain columns send no `options` key at all. Kong gotcha found by `TestListCreate_FullFlow`: a `[]string` **flag** splits on commas unless tagged `sep:"none"`, which a `Status:select:To do,Done` spec needs; positional `[]string` args do not split. `PostInternal`/`PostInternalForm` now carry Slack's `response_metadata.messages` on the `SlackErrorResponse`, and `api.ClassifyError` appends them to `Detail` - the `[ERROR] missing required field: X` strings are the only documentation `lists.*` has. Unverified live (step 8): whether `lists.columns.create` accepts an omitted `options` for plain columns and an empty `choices` list for a select, what an unbalanced icon value does (rejected locally), and what happens to records holding a choice `set-choices` removed.

## Record writes

Slack Lists record writes (`list record add`/`update`, cmd/list_records.go + pure helpers in cmd/list_values.go) use two differently-shaped internal methods, and the shape difference is the thing to remember: `lists.records.create` addresses columns by **key** and takes one **scalar** per field (`[{key, value}]`, string/bool/number), while `lists.cells.update` addresses them by **id** and takes a **typed** object per cell (`rich_text` block array, `select`/`user`/`date`/`number`/`email`/`channel` arrays, `checkbox` bool, `link` as `[{original_url}]`). Both are built from one `cellWrite` so a column's validation runs once. Validation is complete before the first call because Slack is not a validator here: `lists.records.create` silently drops an unknown key and still creates the record, and stores a select value outside the choices as-is (both measured live 2026-11-04) - the test mock (`recordStore` in cmd/list_records_test.go) models both so the refusal tests prove zero calls, not a server rejection. Input is `COLUMN=VALUE` pairs split on the first `=` **or** a stdin JSON object, never both (`parseAssignments`, decoded with `UseNumber` and in source order); select names match value, then exact label, then case-insensitive label; `multi_select` is `update`-only (the create API takes a scalar; one-of-several is unverified) and takes a comma split positionally or a JSON array; user names go through the session resolver (`listSession.resolver`) before `convertCell`, which is pure, but a **name-shaped channel value takes the `draft create` conditional split**: `resolve.ChannelInputNeedsLookup` picks a resolver built on `NewClient` (workspace token; `cli.newResolver` builds it without displacing the printer's enrichment resolver, and the session `authMethod` is restored after `NewClient` clobbers it), because on Grid the org token answers `enterprise_is_restricted` on both channel-list endpoints and a `#name` would read as `channel_not_found`. The plan's "no two-client split for lists" covered the `lists.*` methods only, not name resolution; the reviewer caught it. Ids and URLs stay on the session client so an org-only credential keeps working (`TestListRecordAdd_OrgOnlyCredential`), and `TestListRecordAdd_ChannelNameResolvesOnWorkspaceToken` uses `runWithTwoCredentials` because the single-token harness cannot see which client made a call (both fail on the one-client build, checked by mutation). Stdin must hold exactly one JSON object; a trailing second object or stray text is `invalid_input`, since the decoder would otherwise apply the first object and drop the rest with exit 0. Clearing (`Status=` or JSON `null`) is allowed only on `update` for `select`/`multi_select`/`user` (`[]`, verified) and rejected for every other type until measured. Record ids are checked against Slack's own `^Rec[A-Z0-9]{8,}$` before `files.info` (the read fixtures' `Rec01AAA` is too short, hence `seededRecID`). `cells.update` echoes only changed cells, so `update` re-reads via `lists.records.info` and renders through `renderRecord`; a failed re-read after a successful write is a partial row (`id`, `list_id`, `error`) via `printPartialRow`, never stderr-only. Numbers are carried as `json.Number` end to end so `3.50` is sent and printed as `3.50`. `readPipedStdin` (cmd/draft.go) is the shared TTY-aware stdin reader. Unverified live: every typed shape except what the plan lists as measured, `multi_select` with several values, email/link/channel on `cells.update`, and `lists.records.info` on a record the user cannot see.
