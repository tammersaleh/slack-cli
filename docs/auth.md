# Auth

Measurements and reasoning behind the rules in `CLAUDE.md`. `CLAUDE.md` holds the current rule for each topic. This file holds how it was found.

## The auth login workspace hint

`auth login`'s stderr hint reads `SLACK_WORKSPACE`/`SLACK_WORKSPACE_ORG` via `os.Getenv`, not `cli.Workspace`: kong merges `--workspace` into the same field, and a one-shot flag on login is not the persistent default the hint describes. It matches by exact credentials map key - the same lookup `ResolveCredentials` does - against every stored workspace (a re-login can add workspaces without changing the default), so it never affirms a value a later command would reject. For `SLACK_WORKSPACE` it also never calls stale a value `ResolveCredentials` would accept (an `E` id there is legal, and the org-only fallback depends on that); `SLACK_WORKSPACE_ORG` counts as set only for a stored `E` id, since a `T` id there is a real credential of the wrong kind (`team_is_restricted` on internal APIs). Rows sort by team name then id. Until 2026-09-04 `DesktopLogin` ranged a map and the hint picked the first non-org entry, so the order and the one suggested workspace changed every run and read as "you have no workspace set" when the env was already right; it now lists every candidate because there was no basis for picking one. `--workspace` is team-ID only - `ResolveCredentials`, `auth status`, and `auth logout` all look the value up as the credentials map key, and nothing compares `TeamName`; the flag help used to promise "name or ID" (corrected 2026-09-04 rather than adding name matching, since a Grid org and its workspace can share a name).
